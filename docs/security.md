# Security

Write and read bearer tokens are separate. The write credential only accesses ingestion, while the read credential only accesses status and routing. Identical read and write tokens disable both roles. Compare token digests in constant time. Store service tokens as sensitive Vercel environment variables; the Neon integration manages the database connection variables. The local collector also needs the write token; on macOS it can read a generic password from Keychain (`llm-usage-write-token`, account `llm-usage`) instead of a shell environment variable. Never log request headers, tokens, provider credentials, or raw provider responses. Provider CLI credentials remain on the Mac.

The dashboard uses a separate high-entropy `DASHBOARD_PASSWORD` stored as a sensitive Vercel Production secret. Login sets an HTTP-only, Secure, SameSite=Strict signed cookie that expires after 30 days; the password and API read token are never sent to client-side JavaScript or embedded in the page. Sign out clears the cookie. Dashboard pages are dynamic, marked no-index, and require login before reading account data. Treat this first version as a single-owner service; rotate leaked tokens or dashboard passwords. Migration and account provisioning require database access, not either API token.
