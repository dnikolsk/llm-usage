# Security

Write and read bearer tokens are separate. The write credential only accesses ingestion, while the read credential only accesses status and routing. Identical read and write tokens disable both roles. Compare token digests in constant time. Store service tokens as sensitive Vercel environment variables; the Neon integration manages the database connection variables. The local collector also needs the write token; on macOS it can read a generic password from Keychain (`llm-usage-write-token`, account `llm-usage`) instead of a shell environment variable. Never log request headers, tokens, browser sessions, HTML, or raw provider responses. Collector browser profiles and provider credentials remain on the Mac. Treat this first version as a single-owner service; protect deployments from public indexing and rotate leaked tokens. Migration and account provisioning require database access, not either API token.
