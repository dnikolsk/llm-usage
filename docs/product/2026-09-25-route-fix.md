## Locked product decisions

1. **`execution_reason` must match why placement won**, not the first failed cloud gate.
   - Quick / small local default → e.g. `quick_local` or `small_task` (pick one stable enum; document it).
   - Mac or high interaction → `mac_dependencies` / `interactive` (existing OK).
   - Large unattended + repo ready + confidence OK → `unattended_large_job`.
   - Cloud blocked because repo not ready → `repository_not_ready_for_cloud` **only when cloud was otherwise in play**.

2. **Unknown / ineligible continuity must warn.**
   - If `project.current_account_id` or `current_model` is missing from inventory or ineligible, set `project_continuity=false` **and** add a warning such as `continuity_account_unknown` / `continuity_model_unknown` / `continuity_ineligible`.
   - Docs example currently uses `openai-personal`; prod inventory uses `chatgpt-personal`. Fix docs to match real ids **and** make unknown ids observable.

3. **POST candidates must explain non-winners across accounts**, like GET.
   - Include exhausted / reserve-blocked accounts with exclusion reasons, not only model rows under the winner.

4. **Quality gate: one rule for large work.**
   - Document the difficulty (or model-class) threshold that marks `quality_below_task`.
   - Same `estimated_work=large` + similar difficulty must not silently prefer Sonnet on Mac and Opus on cloud without an explicit, documented reason. If Mac large still allows Sonnet, say so in `reason` / docs; otherwise apply the same quality floor.

5. **Low Jev confidence must not firm-cloud.**
   - If `jev_confidence` is below **0.5**, do **not** return `execution=cloud` or a cloud `handoff`.
   - Stay local (or omit handoff) and keep `low_jev_confidence` in warnings.

6. **OpenAPI / docs** updated for POST candidate shape, new `execution_reason` values, new warnings, confidence→cloud rule.
