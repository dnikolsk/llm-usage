# Use an existing Chrome sign-in

The unpacked extension at `collector/extension` reads the visible text of the active tab only when you click **Preview** or **Sync**. Chrome retains provider cookies. The extension has `activeTab`, `scripting`, and `nativeMessaging` permissions, with no persistent provider host permissions and no cookies permission. A local native messaging host checks the usage-page URL, parses the text into normalized buckets, and reads the write token from macOS Keychain only for Sync. It never stores page text or cookies.

1. In regular Chrome, open **Extensions → Manage Extensions**, enable **Developer mode**, and choose **Load unpacked**. Select this checkout's `collector/extension` folder. Review Chrome's permissions prompt.
2. Copy the extension ID shown on its details page. Run `pnpm --filter @llm-usage/collector install-native-host <extension-id>` from the repository root. This writes a native-host manifest under `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/` allowing only that extension ID. It also makes `collector/native-host.sh` executable. This checkout and its installed dependencies must stay in place.
3. Open a usage page in the same Chrome profile: Claude Settings → Usage (`https://claude.ai/settings/usage`), Cursor Spending (`https://cursor.com/dashboard/spending`), or ChatGPT Settings → Usage (`https://chatgpt.com/#settings/Usage`). Click the extension and **Preview**. It reports only normalized remaining percentages and unknown meters; no backend is needed for Preview.
4. After the service is deployed, create `~/.llm-usage/config.json` containing `{ "service_url": "https://YOUR-DEPLOYMENT" }`. Ensure the Keychain item `llm-usage-write-token` (account `llm-usage`) contains the service write token. Then click **Sync** on each usage page. The native host posts only normalized snapshots to `/v1/ingest` over HTTPS.

The extension is a user-triggered collector, not a scheduler. An automated refresh would require a separate permission and design. Do not load it on arbitrary pages: the native host rejects URLs outside the three usage pages, but the extension may temporarily read the active page when you click it.
